# 11/12-v5.1

本版只增加经验贝叶斯提示中心化（EB）与三组 8B 判别式专家。代码交付不等待 v5.0 分数；真实 GPU 训练、隐藏测试与公榜增益尚未验证。参数冻结在 [v51_plan.json](artifacts/v51_plan.json)。v5.0 继续存档，不能混用它的 SNR 头文件、训练入口或构建器。

## 验证与构建门槛

所有本地指标都是官方训练行上的 prompt OOF **验证**。不使用三成员 parent/native 配比决定是否提交。主指标为 native 单独的 BA（10 次随机分组，每个 prompt 子组 1–2 篇）及家族内准确率 `具体模型正确数 / 家族正确数`。家族沿用 v4 的厂商家族，三组专家可以跨家族。

- EB：配对 prompt bootstrap 的 BA 差值 95% 下界严格大于 0。先算每次分组的正确率，再平均；不会先平均概率来凭空获得多次分组集成的收益。
- 每组专家：真实组内 OOF 准确率高于 native 在同组标签内的准确率；接入 SAGE 后，全体行的家族内准确率差值 95% 下界大于 0。筛出的专家组合还要再通过同一条件。
- 构建器重新计算是否过门槛，核对预测、checkpoint、代码及 bundle 哈希；只带通过的组件。两个都失败就拒绝构建，不消耗提交次数。保留负结果，新增 API 生成数据需另行决定预算。

置信区间重采样单位为 prompt，4,000 次，指标单位为百分点。三组单独区间是各自的 95% 区间，并非经过多重比较修正的联合显著性保证；筛选组合后的区间也不是独立的新确认集。结果必须带上这一限制，不能声称已经证实公榜提升。历史 86.7% / 66.1% / 76.3% 是用户提供的参考，不强制拟合回这些数字。

SAGE 的门槛和拟合输入使用 native 单独的概率，部署输入是完整公开集成（native 占比仍为 0.40）。这避免以失真的 parent 配比过门槛，但无法在本地证明完整集成上的同等增益。旧 parent 代理和之后补录的 v5.0 公榜分只作辅助。公开 native 五折是既有冻结资产，不重新构造其完整嵌套训练；新增专家通过双折排除切断额外的外折标签路径。

后续在 `artifacts/v51_leaderboard.json` 补录 native 0.3/0.4/0.5、v2、v4、v5.0 的真实公榜与对应冻结代理分，执行 `python scripts/v51_proxy_aux.py` 查看辅助拟合和留一误差。未知值保持 null，不猜读数；记录不足时输出 PENDING_SCORES，完全不阻塞训练、门槛或代码交付。

## 两个组件

**EB：**第四张卡运行固定公开 `qwen_groups.py` 与五个 native 折的前向，按完整外部话题面板提取约六万行、至少一千个面板。CPU 上先减去外部类别均值、加上类别均衡均值，防止“某话题只有某模型”成为回归目标；用 128 维固定投影与 ridge 回归预测 centered 头的话题均值。每个 native 外折模型的回归参数和收缩系数都只在外部 prompt 五折上选择；官方外折标签不参与选择。这是比用官方内折选参数更保守的嵌套方案。

部署均值为 `n/(n+τ) × 实测组均值 + τ/(n+τ) × 话题预测均值`。单篇也启用 centered 头，温度和 centered 权重沿用公开校准。Notebook 保留已经算好的 `E_q`，只多做小矩阵计算，没有新增 transformer 前向，也不改 native 头权重。EB 失败或缺少 `E_q` 时删除输出并报错。

**三组专家：**`gemini` = 3.6/3.7/3.8-flash；`glm_claude` = glm-5.3 / flash / claude-fable-5；`gpt_kimi` = gpt-5.5 / gpt-5.6-luna / sol / terra / kimi-k3。每组从固定 Qwen3-Embedding-8B 底座初始化新的 rank16 LoRA 与分类头，判别式 CE；先外部 1 epoch，再官方 2 epochs，固定最后 checkpoint，训练后立即在同一 GPU 对排除的官方行打分。外部各类全部合格数据参与，循环小类实现均衡，不截掉大类；保留约 5% 外部 prompt 作独立校准资源。

除了五个单折排除模型，每组还生成十个双折排除模型：外折 k 的 SAGE 训练行属于 j 折时，专家必须同时没见过 k、j。后者仅用于验证重排，不上传部署。每个训练阶段支持断点，完成训练但未完成打分时记录 `TRAINED`，下一窗口优先补 GPU 打分。

SAGE 复用 v4 条件 logit 引擎，用行内相对专家概率替换 A2，C 固定 0.3；关闭重复的排版特征，不重启 A1/A2。只有前两候选同属一个通过门槛的专家组时才路由。Kaggle 每行最多运行一个专家的一个折，折号为 `sha256(id) % 5`；不会每行跑五折或三个专家。未路由行保留输入决策；已路由行必须完整打分才能生成提交。

服务器单个专家使用一张 32GB Ada；Kaggle FP16 8B 专家由一个进程拆到两张 T4，按组依次加载，避免在 16GB 单卡上加载完整 8B。使用与 native 相同的 16/20 层切分，不引入未经验证的量化精度变化；实际双 T4 显存和耗时仍需真实 smoke 确认。

## 公开数据

已在 2026-11-14 查询 [Open Pool](https://www.kaggle.com/datasets/crtproduction/name-that-llm-open-pool) 最新 v15：主表 226,191 行，其中 gemini-3.7-flash 3,541 行；另有 10,838 行未核验补充。两份 Parquet 的 SHA256 已固定。新增来源已随 v15 合并；仓库不包含数据正文。`v51_data.py` 剔除官方文本/话题重合、冲突重复、已知路由风险等；实际清洗数量写入 `cache/external_v51.json`，不能把原始数量当作可训练数量。

未核验表默认隔离，不会用“文件能读”作为通过核验的依据。已有 native8B、Qwen14B、Llama8B 等三个独立公开模型的 GPU 预测后，用 `v51_screen.py` 合并筛选记录：至少 2/3 top1 同意，gemini3.7 平均概率至少 0.8。每份输入 NPZ 要包含 `ids, labels, probs`，JSON 要包含 `payload_sha256, source_sha256, model_id, checkpoint_sha256`，严格对齐原始行；三个折或同一模型别名不能充当三个独立模型。缺少真实预测就继续隔离，并在交付里说明，禁止伪造票数。这个筛选只控制数据质量，不保证被接纳的路由身份一定正确。

`v51_screen_infer.py` 已提供三个公开成员的真实 GPU 打分入口：native 直接复用固定五折；q14v5/ll8v5 从固定 Notebook 抽取原样 `l24_predict`，只取 plain 分类器，不执行 Notebook 的提交管线。按 `artifacts/screen_*.example.json` 把已有公开底座与五折 adapter 的本地绝对路径填入各自的 spec；公开成员的定位和来源以固定 Notebook setup 为准，不能换成未核验的自训练头。先用 `--member native8b`，再用 `--member q14v5 --spec /ABS/q14.json` 和 `--member ll8v5 --spec /ABS/llama.json`，每条都传实际 `--deadline` 并限定授权 GPU。共享服务器须由实时租约监护进程包裹这些前向；独占窗口自带到期硬停止。完成这一步后再冻结筛选后的正式外部数据、启动训练。

```bash
# 已有三个独立模型对未核验文件的真实 GPU 推理输出时才执行：
CUDA_VISIBLE_DEVICES='' python scripts/v51_screen.py --scores cache/native8b_screen.npz cache/q14v5_screen.npz cache/ll8v5_screen.npz
CUDA_VISIBLE_DEVICES='' python scripts/v51_data.py --screen cache/gemini37_screen.npz
```

新版本文件若与固定 SHA 不同，先审计新版本并冻结计划，不静默替换。已训练运行的数据不可被新的筛选结果覆盖：为新配置另建运行目录。

## 四卡运行与检查

在 `11/12-v5` 下运行，环境沿用 `../11/requirements.txt`。预备公开资产不启动训练：

```bash
python ../11/scripts/assets.py native
python ../11/scripts/assets.py notebook
python ../11/scripts/assets.py backbone
python ../11/scripts/assets.py stage
CUDA_VISIBLE_DEVICES='' python scripts/v51_data.py --download
CUDA_VISIBLE_DEVICES='' python -m unittest discover -s tests -p 'test_v51_*.py' -v
python scripts/run_v51.py --dry-run
```

本地已有资产可经哈希核验后复用。`--download` 查询当前文件，版本改变时会拒绝继续；本地无固定快照则从有权限的历史快照获取，不能改哈希绕过核验。不会运行旧 capped9500 数据重建或旧 native 续训。

专用四卡窗口可以用明确的到期时间；下面是用户指定的 #510 窗口，示例时间不代表实际授权检查已完成：

```bash
python scripts/run_v51.py --smoke --gpus 0,1,2,3 --deadline 2026-11-15T14:00:00+08:00
python scripts/run_v51.py --gpus 0,1,2,3 --deadline 2026-11-15T14:00:00+08:00
```

有 gpubook 的共享服务器必须用实时租约适配器：`--lease-command /absolute/path/lease_argv.json`，文件内容是查询命令 argv 列表；每 10 秒读取最新结果。标准输出只输出 JSON，例如 `{"allowed":true,"gpus":[0,1,2,3],"deadline":"2026-11-15T14:00:00+08:00"}`。`gpus` 需包含当前有权使用且空闲或已由本启动器占用的卡，不能包含他人占用的卡。预约尚未开始/被取消时返回 `allowed:false`；到期前 180 秒保存释放，期限缩短/范围变化会终止受影响进程组并排队。查询失败按无权限处理。适配器须核对实际本人（本工作区最新说明为廖子杰）与实时预约，不能把旧 owner 字段或旧快照当授权。

四个任务独立补位，不要求四卡同时空闲。队友独占四卡可直接给有效截止时间；预约系统上禁止用静态 `--deadline` 代替实时检查。smoke 使用独立 `runs_v51_smoke/`，每组仅两步、少量 GPU 打分，不产出可提交门槛。正式默认 `runs_v51/`，重复相同命令续跑，退出码 75 表示阶段保存暂停。时间预估不是保证：除主外部训练外，还有双折排除、五折打分、加载与 I/O，必须先 smoke 计时。

完成后自动 CPU `v51_evaluate.py`，也可单独执行；只完成 EB 时可用 `--eb-only`，这会明确禁用专家。保存 `evidence/decision.json`、`oof_predictions.npz`、`eb_models.npz` 与 `sage_bundle.json`。`status.json` 可作为 FocusForge 状态适配的原始源；它不替代正式登记或 GPU 使用权限。

```bash
CUDA_VISIBLE_DEVICES='' python scripts/v51_evaluate.py
python scripts/build_v51.py --username YOUR_KAGGLE_USERNAME
python scripts/publish_v51.py               # 只预览
python scripts/publish_v51.py --submit      # 过门槛后发布并提交一次
```
